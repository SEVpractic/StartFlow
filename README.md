# StartFlow

Маленькая персональная Windows 11 utility для подготовки рабочего окружения при запуске.

Один раз настраивается, что должно происходить при старте:

1. Создать папку по шаблону.
2. Открыть определённые папки в Windows Explorer.
3. Запустить определённые приложения (возможно, от имени администратора).

## Требования

- Windows 11 (x64)
- .NET 9 SDK для сборки (проект WinUI 3 / Windows App SDK)
- Собранный `StartFlow.exe` — самодостаточный (run included), никаких зависимостей не требует

## Сборка

```powershell
dotnet restore
dotnet build StartFlow.csproj -c Release -r win-x64 --self-contained true
```

Результат появится в:

```text
bin\Release\net9.0-windows10.0.26100.0\win-x64\StartFlow.exe
```

## Запуск GUI

```text
StartFlow.exe
```

Открывается окно приложения с двумя экранами: **Обзор** и **Настройки**.

## Запуск silent mode

```text
StartFlow.exe --silent
```

Окно GUI не показывается, конфигурация выполняется, процесс завершается.

Exit code:

- `0` — все операции выполнены;
- `1` — были ошибки;
- `2` — критическая ошибка.

Другие аргументы:

```text
StartFlow.exe --help
```

## Хранение данных и профили

Все данные хранятся в профилях в папке:

```text
%LOCALAPPDATA%\StartFlow\
├── state.json          — активный профиль
├── profiles\           — файлы профилей (один JSON на профиль)
├── backups\            — резервные копии и карантин повреждённых файлов
└── logs\               — карантинные копии (если таблица карантина пуста)
```

Файл профиля (конверт):

```json
{
  "schemaVersion": 1,
  "name": "Development",
  "config": {
    "folderGeneration": [],
    "foldersToOpen": [],
    "programs": [],
    "theme": "dark"
  }
}
```

### Поведение

- При первом запуске (папка `%LOCALAPPDATA%\StartFlow` отсутствует) создаются структура папок, `state.json` и пустой профиль `Default`.
- Активный профиль хранится отдельно в `state.json` (`"activeProfile": "Default"`) и не определяется по имени файла.
- `schemaVersion` нужен для будущих миграций: если версия файла старше текущей, профиль проходит цепочку миграций `MigrationService` перед чтением. Если версия новее — приложение показывает предупреждение и не трогает файл.
- Перед миграцией или восстановлением повреждённого файла создаётся резервная копия в `backups\`. Обычный запуск приложения резервные копии не создаёт.
- Повреждённый профиль переносится в `backups\` с суффиксом `_bad_<дата>.json`, приложение создаёт профиль с настройками по умолчанию и показывает предупреждение в GUI.
- Нельзя удалить последний профиль; нельзя создать/переименовать профиль в недопустимое имя (пустое, с зарезервированными именами `CON`, `PRN`, `AUX`, `NUL`, `COM1–9`, `LPT1–9` и т.д.).
- Переименование активного профиля автоматически обновляет `state.json`.
- Старый файл `config.json` (или `startflow.json`) рядом с исполняемым файлом:
  - **не используется** и **не читается** новой версией;
  - **не удаляется** и **не переносится** — остаётся как есть на случай отката.

### Управление профилями

Экран **Настройки** → карточка «Профили» позволяет:

- выбрать активный профиль;
- создать, скопировать, переименовать и удалить профиль;
- экспортировать профиль в файл (JSON, выбирается через стандартный диалог сохранения);
- импортировать профиль из файла (при совпадении имени предлагается перезаписать или импортировать под новым именем).

Каждый профиль содержит свою настройку темы (`default` / `dark`) и свой набор папок и программ. При выборе профиля «Обзор» и «Настройки» показывают данные активного профиля.

### Silent mode

`StartFlow.exe --silent` выполняет конфигурацию **активного профиля** и завершается. В консоль выводится имя профиля. GUI и диалоги не используются.

Пример формата конфигурации (сервисное представление команды программы):

```json
{
  "folderGeneration": [
    {
      "enabled": true,
      "openAfterCreate": false,
      "path": "D:\\Homework",
      "template": "Homework {date}"
    }
  ],
  "foldersToOpen": [
    {
      "path": "D:\\Homework",
      "enabled": true
    }
  ],
  "programs": [
    {
      "name": "Visual Studio",
      "path": "C:\\Program Files\\Microsoft Visual Studio\\2022\\Community\\Common7\\IDE\\devenv.exe",
      "args": "",
      "workingDirectory": "C:\\Program Files\\Microsoft Visual Studio\\2022\\Community\\Common7\\IDE",
      "runAsAdmin": true,
      "skipIfRunning": true,
      "processName": "devenv",
      "enabled": true
    }
  ],
  "theme": "default"
}
```

В шаблоне имени поддерживается подстановка `{date}` — текущая дата в формате `дд.ММ.гггг` (например, `Homework 17.09.2026`).

## Создание ярлыка для автозапуска окружения

1. Найдите `StartFlow.exe` в папке сборки.
2. Кликните правой кнопкой → **Показать дополнительные параметры** → **Создать ярлык**.
3. Перенесите ярлык на рабочий стол.
4. Кликните ярлык правой кнопкой → **Свойства**.
5. В поле **Объект** добавьте ` --silent` в конец:

   ```text
   "...\StartFlow.exe" --silent
   ```

6. Нажмите **ОК**.

Теперь двойной клик по ярлыку выполняет полный запуск рабочего окружения без окна StartFlow.

## Добавление приложения из списка установленных

Кнопка **Добавить** в карточке «Программы» предлагает два способа:

- **Выбрать из установленных приложений** — показывает список приложений из Windows («Все приложения» / `shell:AppsFolder`) с иконками и поиском. Программа добавляется с автозаполнением: `Name`, `Path`, `WorkingDirectory`, `ProcessName` (для `.exe`), `Args`.
- **Найти exe вручную** — стандартный диалог выбора файла (прежний способ).

Ограничения:

- Список формируется из зарегистрированных в Windows ярлыков; диск не сканируется.
- Приложения Store (UWP/MSIX) отображаются в списке, но не могут быть добавлены: у них нет пути к исполняемому файлу, они запускаются только через Windows. Для таких приложений используется способ «Найти exe вручную» (если приложение предоставляет exe).
- Для не-`.exe` запускаемых файлов (например, `.msc`, `.cmd`) поле `ProcessName` остаётся пустым, поэтому `skipIfRunning` для них не сработает.

## `runAsAdmin`

Если у приложения включён `runAsAdmin: true`, оно запускается через Windows Shell с verb `runas`. UAC не обходится — Windows покажет стандартный запрос подтверждения.

## `skipIfRunning`

Если у приложения включён `skipIfRunning: true`, указывается `processName`, и такой процесс уже запущен — приложение пропускается (считается в «Пропущено»). Если `processName` пустой, проверка пропускается, приложение запускается. `.exe` в имени процесса не обязателен — он отбрасывается автоматически.

## `workingDirectory`

Рабочая директория, с которой запускается приложение (например, для OBS Studio нужен каталог рядом с `obs64.exe`). Если `workingDirectory` не указан или пустой, автоматически используется директория, содержащая исполняемый файл из `path`. Свойство необязательное — старые конфигурации без него продолжают работать.

## Примечания

- Конфигурация не использует реестр и базы данных.
- Пользовательские данные не отправляются никуда — приложение полностью офлайн.
